# ZERO-IG official per-image training feasibility, synthetic only

2026-09-25 16:04+08. Official source: [Doyle59217/ZeroIG](https://github.com/Doyle59217/ZeroIG), commit `5af4b8aca6b114732f05d7fea70e0fbc874d63ab`. The README explicitly says the shipped weights are not the paper-result model and recommends training on a single image; `train.py` defaults to 2001 epochs, Adam lr 0.0003, batch size 1. `multi_read_data.py` does no spatial resize. The one-image training path is target-low-only in principle but has not yet run on the canonical cohort. No target image/reference/metric was opened for this probe.

On the paid 48 GB RTX 4090, the unchanged official `Network()._loss` plus backward passed on one deterministic 352×352 synthetic RGB image: finite loss 2693.0498, 0.412 s, 977,272,832 bytes peak reserved VRAM. The same one-step unchanged computation on a 2160×3840 synthetic RGB tensor failed with CUDA OOM in official `utils.calculate_local_variance` at `(unfolded_noisy-unfolded_noisy_avg)**2`, attempting a further 2.32 GiB allocation. No optimizer step was completed at 4K. This is an observed execution blocker, not a target result. Whole-image downscaling or crop training would change the official single-image objective and cannot be silently treated as equivalent.

ZERO-IG status: `BLOCKED_EXECUTION_4K_MEMORY` provisionally, as a preferred **additional** row only. It must not delay Tier-1. Before reference opening, its inclusion/terminal status must be locked in the output gate. `reference_reads=0`, `target_model_runs=0`, `metrics=0` for this probe.
