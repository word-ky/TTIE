## Full-component synthetic execution update (2026-09-25)

On the paid 48 GB RTX 4090, the pinned five-task PromptIR checkpoint and unchanged upstream SRTTA/RDDM adaptation ran end-to-end on a single deterministic 352×352 RGB **synthetic low-only** image. Both static and DCTTA output files were 352×352 RGB; the DCTTA PNG SHA256 is `1edc39b3ed85fc4bc33443bf3430f59eea2b39883a7b025ea760288118294216` (static `aaae9fb74906722999086b0d5ee04e4fc90a53c5a5e2bd9e3e606f5d7cfb2ad1`). A repeat DCTTA run with cached VGG19 weights took 10.650 seconds end-to-end and reported 23,897,047,040 bytes peak reserved GPU memory. VGG19 weight SHA256 is `dcbb9e9dad569fff7a846263a77324fc34978fea2bfb039c012d710e1776ae44`. GPU had no leftover compute process after completion. Initial static launch failed on an import-order collision (`RDDM.net` shadowed `net.model`); the only repair was to import RDDM after PromptIR initialization in the task runner. All four focused tests passed afterward. No target image, target reference, or metric was used. This confirms real execution, **not yet** independent low-only gate acceptance or target scientific validity.

The official DCTTA repository is pinned at `0526bf7b87c2a54574ae1cb3af916fd5568fc0b1`; `tta.py` is unmodified (SHA256 `d101d7f55d69efe90c2b79b6a0b530079c7da4dca0a235490a1df9d552084f95`). Both static PromptIR and DCTTA use the same official five-task `epoch=80.ckpt` (SHA256 `206baf0dd10f636f025b33b5ee7eb63a353fcbf4d50858b62f9480a6d4be9d4a`), which loads all 548 state keys with strict matching.

The official paired training dataset yields `(name, degraded, clean)`. Its Fisher implementation transfers `clean` to CUDA but never reads it in the Fisher loss; the official adaptation call receives only the loader, degraded tensor, name, and redegradation model. The task-owned training dataset returns the identical degraded patch sequence and an LQ surrogate in the otherwise unused third slot. On three equal-size synthetic pairs, degraded tensors were bitwise equal across the ordered sequence. The low-only inference dataset also matched the official paired inference loader bitwise, including center crop to a multiple of 16. Neither task-owned dataset accepts a GT directory.

The task-owned runner calls the unchanged official `tta.SRTTA`, `compute_fisher`, redegradation model, and final PromptIR model; it does not import either official paired entrypoint or call a target-reference metric. A synthetic runner test observed only three LQ opens across Fisher, adaptation, and inference; injecting a GT open produced `PermissionError`. A source-side test used the actual upstream Fisher, teacher/student update, wavelet transform, optimizer, and Fisher-restoration code on paired versus low-only inputs: degraded tensors, Fisher values/masks, restored tensor and final model state were exactly equal. That test used a toy restorer, deterministic toy redegradation and a substituted simple loss to keep the comparison bounded. It **does not** reproduce full PromptIR+RDDM+VGG adaptation and must not be described as such. One separate 32×32 synthetic CPU forward of the real five-task PromptIR produced finite float32 output at the expected shape.

The only source edit so far is the recorded lazy import of `mmcv.ops` inside the unused DCN layer; PromptIR and DCTTA adaptation code are untouched.
